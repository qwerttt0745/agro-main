# Прості відповіді та кнопка «Стоп»

## Проста мова

Одна мовна інструкція в `app/language.py` застосовується до текстових відповідей, фото й голосу незалежно від обраної моделі. Короткі речення, спочатку відповідь по суті, далі кілька зрозумілих кроків. Спеціальний термін, якщо потрібен, відразу пояснюється.

Приклади налаштування: «посів» замість «сівба», «що росло на цьому полі раніше» замість «попередник», «сорт, який підходить для цієї місцевості» замість «районований сорт». Цитати в розділі джерел лишаються дослівними. Перевірка фактів, чисел і одиниць не послаблюється. Інструкції перевірено в тестах; реальні мовні відповіді серверного Gemini ще потребують перевірки батьком.

## Як зупинити запит

Після надсилання повідомлення стрілка перетворюється на квадрат **■** з підказкою «Стоп». Натисніть його — застосунок надішле захищену команду скасування, покаже «Запит зупинено» і знову дозволить писати.

Прийняте сервером питання залишається в історії. Можна натиснути **Повторити запит** або написати нове. Якщо скасування надійшло під час завантаження запиту, який ще не дійшов до сервера, збереження не можна гарантувати. Після підтвердженого скасування пізня відповідь не додається в історію.

Скасування діє на рівні застосунку: нові виклики моделі/перемикання/виправлення цитат більше не запускаються. Синхронний запит, який уже отримав Google, може завершуватися до таймауту й витратити квоту; це не гарантія відкликання обчислень або платежу у провайдера. Локальне CPU-обчислення теж завершує поточний крок, перш ніж перевірить прапорець зупинки.

Збереження відповіді та команда скасування узгоджуються блокуванням. Якщо збереження завершилося раніше, команда поверне `completed`, і браузер покаже готову відповідь. Якщо першим було скасування — відповідь не збережеться.

## Технічні деталі

- `POST /chats/{id}/ask`: необов'язковий `request_id` у JSON.
- `POST /chats/{id}/retry`: необов'язкове JSON-тіло з `request_id`.
- `POST /chats/{id}/cancel`: обов'язковий `request_id`; потрібні сесія, CSRF-заголовок та власність чату.
- Старі клієнти без номера запиту продовжують працювати.
- Ідентифікатори розділені за користувачами. Чужий запит не скасовується.
- До 2 незавершених робіт на користувача (включно зі скасованими, поки старий виклик фактично завершується) та 16 на процес. Це обмежує накопичення фонових запитів після багаторазового натискання «Стоп».
- Реєстр скасувань зберігається у пам'яті процесу. Підтримується поточна конфігурація Docker з одним worker. Для кількох workers/реплік потрібне спільне сховище керування завданнями; не збільшуйте workers без цього.
- Compose, Caddy, HTTPS, паролі та приватні записи цією функцією не змінюються.

## Попередні виправлення, включені до цього оновлення

Ліміти входу розділено за IP + логіном: невдалі входи одного акаунта не блокують усі інші за тією самою мережею. Залишився широкий захисний ліміт IP. Новий допоміжний лічильник не змінює хеші, солі чи сесії користувачів. Якщо причина була в старому спільному ліміті, скидати паролі не потрібно. Активність акаунта сама по собі не доводить, що введений пароль правильний.

Загальне питання «Як правильно вирощувати пшеницю?» більше не повинно перетворюватися лише через помилковий прапорець моделі на шаблон про пестициди або добрива. Для загального огляду залишаються обов'язковими точні цитати; конкретні норми засобів чи добрив у такій відповіді відправляються на виправлення. Продовження «Ну напиши як правильно вирощувати» бере назву культури з повідомлень користувача, а не з попереднього хибного шаблону помічника. Якщо перевірених даних немає, застосунок не вигадує відповідь.

## Оновлення

Після commit/push усіх локальних змін на сервері:

```bash
cd /opt/agro
docker compose exec app python -m scripts.backup
git pull --ff-only
docker compose build app
docker compose up -d --no-deps --force-recreate app
docker compose logs --tail=50 app
```

Повторна міграція користувачів не потрібна. Старі таблиці й акаунти не видаляються. Для обмежувача входів при роботі створюється нова допоміжна таблиця, попередні лічильники лишаються недоторканими.

## Перевірки

Повний набір: **165 passed, 16 subtests passed in 33.60s**.
Браузерна перевірка на ширині 390 px: зупинка під час повільної відповіді, швидке повернення керування, відсутність пізньої відповіді, скасування повторної спроби, нове питання після зупинки, розмір кнопки та відсутність JS-помилок. Також перевіряється сумісний спосіб створення номера запиту для браузерів без `crypto.randomUUID`.

Тести використовують тимчасові дані й контрольовані AI-відповіді. Production і реальні акаунти не змінювалися.
