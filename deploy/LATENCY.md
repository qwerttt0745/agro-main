# Діагностика довгих відповідей Agro AI

Очікування 1–2 хвилини на кожне текстове питання потребує вимірювання на сервері. Скриншот із `invalid_evidence` підтверджує невдалу перевірку цитат, але не визначає, який етап зайняв більшість часу.

## Локальні зміни

- Самодостатні короткі питання з явною культурою (наприклад, «де садить пшеницю?») не потребують додаткового виклику Gemini для переформулювання. Контекстні продовження на кшталт «а для нашого поля?» і далі враховують історію.
- Переформулювання: одна спроба, мережевий таймаут до 5 секунд. У разі збою пошук продовжується за оригінальним питанням; історія залишається в промпті відповіді.
- Основна відповідь: до двох повільних спроб, до 15 секунд на спробу. Швидкі відмови API (менше секунди) через квоту, відсутню модель чи перевантаження дозволяють перейти далі по ширшому пулу в межах того самого загального бюджету.
- Виправлення цитат: одна повільна спроба до 10 секунд у межах спільного бюджету; швидка відмова API дозволяє перейти на іншу модель. Непідтверджені цитати не приймаються.
- Бюджет текстової обробки зменшено з 90 до 45 секунд; фото — зі 120 до 75 секунд. Для початкового аналізу фото — до двох спроб по 20 секунд.
- Для Gemini 3.8 Flash, 3.6 Flash і 3 Flash Preview задано підтримуваний рівень thinking LOW. Для інших моделей thinking-конфігурація не змінюється. Явний temperature більше не передається.
- Локальний encoder використовує один CPU thread за замовчуванням, щоб зменшити конкуренцію на малих VM. Адміністратор може змінити `AGRO_EMBEDDING_THREADS` через env-файл застосунку та перезапустити контейнер.
- Інтерфейс показує тривалість очікування, а після 20 секунд — повідомлення про довшу обробку. Це таймер, а не імітація серверних етапів.

Числа є бюджетами викликів і мережевими таймаутами, а не жорсткою гарантією тривалості HTTP-запиту. Ініціалізація моделі, CPU-навантаження, черги й особливості мережевого таймауту можуть їх перевищувати. Нова конфігурація перевіряється на сервері за замірами; реальна швидкість і якість відповідей Gemini локально не вимірювалися. За проблем із квотою зменшення бюджету може означати швидшу відмову, а не успішну відповідь.

## Оновлення сервера

Після commit/push локальних змін, у `/opt/agro`:

```bash
git pull --ff-only
docker compose build app
docker compose up -d --no-deps --force-recreate app
```

Міграція баз для цього оновлення не потрібна.

## Що надіслати для діагностики

Відкрийте застосунок і поставте 2–3 звичайні текстові питання. Потім виконайте:

```bash
cd /opt/agro
docker compose logs --since=15m app | grep -E 'agro_perf|Gemini switch'
docker stats --no-stream
```

Нові рядки мають вигляд:

```text
agro_perf trace=... stage=embedding_encode seconds=... status=ok
agro_perf trace=... stage=provider seconds=... status=ok model=... attempt=1 ...
agro_perf trace=... stage=citation_validation seconds=... status=ok result=invalid_evidence
agro_perf trace=... stage=request seconds=... status=ok kind=text
```

Приклади показують формат, а не виміряні значення.

- `embedding_load`: завантаження локального encoder, переважно перший запит після запуску.
- `embedding_encode`: CPU-обчислення вектора питання.
- `library_open`, `vector_search`, `retrieval`: відкриття бібліотеки, пошук і підготовка сторінок. `retrieval` включає вкладені етапи — їх не потрібно додавати до нього ще раз.
- `rewrite`: допоміжне переформулювання питання.
- `provider`: окрема спроба Gemini, модель, таймаут, тривалість і факт помилки.
- `answer_generate`: основна генерація, кількість символів контексту й джерел.
- `citation_validation`, `citation_repair`, `repair_validation`: перевірка, виправлення та повторна перевірка цитат.
- `request`: загальний час виконання AI-відповіді всередині застосунку; початкова підготовка фото/збереження питання та час очікування HTTP-worker перед цим заміром сюди не входять.

Рядки одного запиту пов'язані випадковим `trace`. Тексти запитів/відповідей, координати, логіни, паролі, токени та API-ключі до цих вимірів не потрапляють; текст винятку провайдера не друкується.

Спочатку порівняйте перший і наступні запити, час `provider` та `embedding_encode`, помилки квоти/перемикання моделей і частоту `invalid_evidence`. Це дозволить відрізнити проблему CPU, мережі/моделей і цитування.

Підстава для модельних налаштувань: [Gemini thinking](https://ai.google.dev/gemini-api/docs/thinking), [Gemini troubleshooting](https://ai.google.dev/gemini-api/docs/troubleshooting). Підтримку параметрів також перевірено в установленому Python SDK.
