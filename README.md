# Агрономічний помічник

Локальний помічник українською для господарства в Паволочі. Поточна версія — прототип із бібліотекою PDF та історією чатів, без авторизації.

## Запуск

Команди виконуються з папки проєкту:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
./start.sh
```

Відкрити http://127.0.0.1:8000. Сервер працює в поточному терміналі, зупинка — Ctrl+C. Запуск не завершує чужі процеси. `.env` завантажується автоматично; потрібен `GEMINI_API_KEY` (або `GOOGLE_API_KEY`). Не зберігайте ключі в Git. Модель задається через `GEMINI_MODEL`; початкове значення збережено: `gemini-3.8-flash`. Наявність доступу до цієї моделі для конкретного ключа потрібно перевірити окремо.

Залежності моделей та база векторів завантажуються лише під час першого питання. Перше завантаження embedding-моделі потребує інтернету. Відсутність ключа або збій RAG не перешкоджають відкриттю сайту й перегляду чатів. Автоматичні повтори SDK вимкнено: застосунок сам робить до двох спроб основної моделі та одну резервної (лише для тимчасових збоїв). Резервна модель — `gemini-3.5-flash-lite`; змінна `GEMINI_FALLBACK_MODEL` змінює її, порожнє значення вимикає резерв. Для 429 та помилок конфігурації повторів немає. Таймаут одного виклику — до 20 секунд; обидва етапи Gemini ділять бюджет 60 секунд від початку обробки питання. Локальна індексація/embeddings не перериваються цим бюджетом. Після його вичерпання новий виклик Gemini не починається.

## Бібліотека

```sh
.venv/bin/python -m scripts.ingest data/pdfs
# Або кілька конкретних PDF:
.venv/bin/python -m scripts.ingest /path/one.pdf /path/two.pdf
```

Оновлюється лише переданий документ. Повторний запуск для того самого шляху й вмісту не створює дублікатів. Застарілі фрагменти цього документа видаляються після запису всіх нових. Відносні шляхи старої версії зіставляються від кореня проєкту. Перенесений чи перейменований файл вважається іншим документом. Старі абсолютні шляхи з іншого комп'ютера потребують окремої міграції.

PDF без видобутого тексту викликає помилку; старі записи зберігаються. OCR ще немає. Запис у Chroma не є атомарним для кількох пакетів: збій посеред запису може залишити частину нових фрагментів поруч зі старими; повторний успішний запуск завершує оновлення. Не запускайте одночасно кілька індексацій одного документа.

Номери сторінок — фізичні сторінки PDF, починаючи з 1. Відповідь має позначки [S1], [S2]. Блок «Джерела» містить документ, сторінку, дослівну цитату й посилання на локальний PDF. Джерела зберігаються разом із повідомленням. Старі повідомлення зберігаються, але автоматично джерелами не доповнюються. Невідомі ID, відсутні посилання або цитати, яких немає у фрагментах, блокують показ відповіді. Перевірка текстового збігу ще не доводить, що цитата логічно підтримує кожне твердження.

## Перевірки

```sh
.venv/bin/python -m pytest -q
```

Тести використовують тимчасову SQLite та окрему Chroma, імітують генерацію й embeddings, не надсилають запити Gemini та не змінюють робочу бібліотеку.

## Наступні критерії готовності

- Перевірити реальний пошук на контрольних питаннях із бібліотеки: очікувані документ, сторінка, ключові факти й питання без відповіді. Після цього вирішувати, чи потрібні hybrid search/reranking.
- Перевірка того, що цитати логічно підтримують кожне твердження. Поточна перевірка встановлює лише наявність цитати в знайденому фрагменті.
- Ідемпотентне повторне надсилання повідомлення та жорсткий загальний таймаут, що включає локальну роботу embeddings.
- Профіль господарства й фото, потім перевірка користі з реальним користувачем.
- Авторизація та ізоляція чатів, резервні копії й захищене розгортання. До цього запуск лише на 127.0.0.1: усі чати доступні кожному, хто має доступ до сервера.
- Голос і камера — окремий етап.

Парсер каталогу ще потребує перевірки: зараз він підставляє 2020 рік, якщо дата невідома. Це не підтверджена дата публікації.

## Контроль якості пошуку

```sh
# Локальний пошук без Gemini (перша загрузка моделі потребує інтернету):
.venv/bin/python -m scripts.evaluate
# Додатково 8 запитів генерації, використовується квота Gemini:
.venv/bin/python -m scripts.evaluate --answers --output evaluation/answers.json
```

Контрольні питання — `evaluation/questions.json`: 5 питань із перевіреними сторінками та фрагментами і 3 питання без відповіді (pH конкретного поля, завтрашня погода, поточна ціна). Початковий top-5 — `evaluation/baseline-top5.json` (2/5 позитивних контрольних питань), top-10 без розширення сторінок — `evaluation/baseline-top10.json` (2/5), top-10 із розширенням — `evaluation/latest.json` (5/5); поточний пошук знаходить 10 фрагментів, прибирає повторні сторінки й підвантажує всі проіндексовані фрагменти кожної знайденої сторінки. Це зберігає відповідь, яка раніше залишалася за межею короткого уривка. Звіти містять знайдені тексти, сторінки та відстані. Відстань не є ймовірністю правильності; поріг відмови за нею не налаштовано.

Для позитивного retrieval_hit потрібні правильні документ, сторінка і контрольний текст. Для answer_check перевіряється відмова на негативному питанні або правильна сторінка цитати на позитивному. Це мала регресійна вибірка; вона не замінює перевірку агрономом, не вимірює повноту відповіді й не гарантує правильності всіх порад.

Остання перевірка генерації (`evaluation/answers.json`) виконана з `gemini-3.5-flash-lite`: 5 відповідей із потрібною сторінкою і 3 відмови, 8/8 автоматичних перевірок. Основна модель у застосунку залишається без змін із резервним переходом. Під час ручного огляду помічено залишкові недоліки: відповідь про глибину сівби назвала коригування без базової глибини, а відповідь про зберігання зерна додала зайве застереження про пестициди. Отже, метрика 8/8 не означає ідеальну повноту чи стиль відповіді.

## Господарство та розширена бібліотека

`/farm` показує надані користувачем координати й сім культур, регіональний клімат NASA POWER за 2016–2025 та каталог PDF. Вхідні дані й розраховані показники збережені в `data/site/`; це не аналіз ґрунту, меж поля чи прогноз. Висота — Copernicus DEM GLO-90 через Open-Meteo. Приватний профіль — `data/farm_profile.json`.

Калькулятор `/api/calculations/nitrogen` перераховує задану кількість N у масу добрива за масовою часткою. Він не підбирає агрономічної норми, строків чи способу внесення. Невідомі характеристики поля залишаються невідомими.

`data/library_manifest.json` містить походження, рік, регіон, дату отримання та статус кожного нового видання. Додано SARE (2021, 2007), FAO (2006) та український журнал (2025). Старі та іноземні книги не є підтвердженням чинної української реєстрації препаратів. Автоматичний доступ до реєстру поки відсутній. Модель має повертати ознаки потреби в етикетці/даних поля; сервер замінює такі відповіді на пояснення відсутніх даних. Визначення цих ознак залежить від моделі та не гарантує виявлення кожного запиту.

Імпорт: `.venv/bin/python -m scripts.import_library --fetch --pdf-only`, потім `--index`. Недоступні джерела не обходяться; `excluded` не індексуються. Перед зміною індексу створюйте резервну копію `data/chroma` за відсутності записів. Повторне завантаження позначає матеріал як downloaded до індексації. Пошук потрібно перевіряти після кожного розширення; результати малої регресійної вибірки не доводять загальної агрономічної точності.

## Фото та перевірка цитат

До запиту можна додати одне JPEG/PNG/WebP до 6 МБ та 20 мегапікселів. Сервер перевіряє фактичний формат, відхиляє анімацію, нормалізує орієнтацію, зменшує зображення до 1600 px та повторно кодує тільки пікселі без EXIF/GPS. Очищене фото зберігається в SQLite разом із повідомленням до виклику Gemini; резервна копія цієї БД містить і фото. Кнопка надсилання передає фото в Google Gemini, про що повідомляє форма. Локальна версія поки без авторизації й слухає лише 127.0.0.1; не публікуйте її без наступного етапу захисту.

Фотоаналіз відокремлює видимі ознаки від пояснень із бібліотеки. Опис не є підтвердженим діагнозом. Для пошуку використовуються ознаки з поточного фото; попередні фото автоматично повторно не надсилаються. Загальний бюджет генерації 60 секунд, спроба розпізнавання фото — до 40 секунд у межах цього бюджету. Якщо пояснення недоступне, зберігається отриманий опис з відповідним повідомленням.

Якщо перевірка цитат відхиляє текстову відповідь, допускається одна повторна генерація у початковому бюджеті часу. Новий текст проходить ту саму сувору перевірку джерел. Перевірка дослівності не доводить логічної відповідності кожного твердження цитаті.

## Автоматичний вибір Gemini (2026-10-20)

Генерація використовує фіксований пул із п’яти моделей у `app/model_pool.py`: Gemini 3.8 Flash → 3.6 Flash → 3.5 Flash-Lite → 3.1 Flash-Lite → 2.5 Flash. Усі були присутні в `models.list` та мали Free Tier для стандартної генерації на офіційній сторінці https://ai.google.dev/gemini-api/docs/pricing під час перевірки. Порядок є налаштованим пріоритетом, а не автоматичним доказом найкращої агрономічної точності. Старі GEMINI_MODEL/GEMINI_FALLBACK_MODEL більше не визначають маршрутизацію. Не додавалися псевдоніми latest, платні-only, TTS, Live чи image-generation моделі.

Кожна модель викликається не більше одного разу за один виклик генератора; приховані SDK-повтори вимкнені. 429 переводить модель на паузу за RetryInfo (мінімум 60 с, без підказки — 300 с). 503, таймаути та порожні відповіді дають паузу 120–900 с; 403/404 — годину. 400/401 зупиняють спробу з повідомленням про налаштування. Стан захищений lock і живе в одному серверному процесі; перезапуск скидає паузи. `/api/models` показує стан без секретів. Нульова пауза означає «можна спробувати», а не гарантію доступності.

Загальний бюджет генерації: текст 90 с, фото 120 с; час розподіляється між ще не перевіреними моделями. Цей бюджет не є жорстким таймаутом локального завантаження моделі пошуку/індексу. Квоти та тариф визначає Google-проєкт; наявність Free Tier у моделі не перемикає платний проєкт у безкоштовний режим. Ключі й білінг не змінюються.

Очікувана недоступність повертається як `status: unavailable` без додавання хибної відповіді асистента. Кнопка «Повторити запит» викликає `/chats/{id}/retry` та використовує останнє збережене повідомлення з фото без дублювання. Якщо всі моделі на паузі, нові виклики Google не виконуються до завершення паузи. Перемикання не гарантує роботу під час загального збою або вичерпання всіх квот.

## Резервна копія чатів і фото

`.venv/bin/python -m scripts.backup` створює окрему копію SQLite через Backup API, включно з фото, а також профіль господарства, каталог джерел і кліматичний підсумок. База перевіряється через `integrity_check`; для файлів зберігаються SHA-256. Перевірка наявної копії: `.venv/bin/python -m scripts.backup --verify data/backups/НАЗВА_КОПІЇ`.

Це локальна копія приватних даних, не повна копія застосунку: PDF, Chroma, програмний код і `.env` не включені. Копія на тому самому диску не захищає від втрати диска. Для відновлення слід зупинити сервер, зберегти поточну БД окремо й лише тоді відновити перевірену `chats.db` та потрібний профіль. Автоматичне видалення старих копій та регулярний розклад не налаштовані.

## Вхід до сімейного господарства

Усі дані тепер доступні лише після входу на `/login`. Обліковий запис один, спільний для господарства: ролей чи окремих просторів кількох фермерів немає. Пароль хешується scrypt із випадковою сіллю. Сервер зберігає лише хеш випадкового session token; cookie HttpOnly, SameSite=Strict, до 14 днів. Вихід видаляє сесію, зміна пароля скасовує всі сесії. Після 5 невдалих спроб з однієї IP за 15 хвилин нові спроби тимчасово блокуються. Дані без налаштованих credentials залишаються закритими.

Локально `AGRO_COOKIE_SECURE=false` дозволено лише для localhost. Для VM обов’язкові `AGRO_COOKIE_SECURE=true`, HTTPS і `AGRO_PUBLIC_ORIGIN=https://домен`. Небезпечні методи API потребують `X-Agro-Request: 1`; Origin перевіряється, якщо присутній. Браузерний клієнт надсилає заголовок сам. Не додавайте дозвільний CORS.

Користувачів створює адміністратор через `.venv/bin/python -m scripts.create_user --username <логін>`; пароль вводиться інтерактивно. Зміна пароля наявного користувача: `.venv/bin/python -m scripts.set_password --username <логін>`; сесії інших користувачів залишаються чинними. Для старої інсталяції потрібна явна міграція з резервною копією: `deploy/MULTIUSER.md`. Інструкція та шаблони для Oracle VM: `deploy/README.md`.

## Виправлення відповідей за контекстом

Контекст діалогу збільшено до 12 повідомлень; оригінальне питання й останні 10 повідомлень передаються генератору разом із переформульованим запитом. Для запиту про масу насіння гречки пошук орієнтується на норму висіву. Перерахунок площі виконує Decimal за реально знайденими нормами у навчальному джерелі з явним роком і обмеженнями застосовності. Без відповідного фрагмента розрахунок не видається. Це окремий перевірений сценарій, а не універсальний агрономічний калькулятор.

Питання про тип ґрунту саме на полі пояснює відсутність обстеження замість вигадування чорнозему. Фотоаналіз може називати можливу рослину з невизначеністю; це не підтверджена ідентифікація чи діагноз. Старі помилкові відповіді в історії не переписуються.

Уточнення враховують попередні питання навіть після збою провайдера без відповіді. Простий повтор того самого питання не потребує переписування. Виправлення цитат отримує той самий контекст та оригінальний запит. Явна маса насіння гречки обходить генеративне переписування, щоб зберегти числа й одиниці користувача.

## Повторна перевірка якості

`HF_HUB_OFFLINE=1 .venv/bin/python -m scripts.evaluate` перевіряє локальний індекс за 13 сценаріями (7 із відомими сторінками, 5 із недостатніми даними, 1 із погодним API). Offline потребує вже завантаженої embedding-моделі. Пошук сам по собі не оцінює якість відмови. `--answers` додатково звертається до Gemini; `--ids buckwheat_sowing buckwheat_mass local_soil` обмежує вибірку. Звіт компактний; повні фрагменти можна включити через `--include-text`. Невдала перевірка повертає ненульовий код завершення. Перевіряються статус, сторінка та задані фрази, але не повна агрономічна коректність.

Точні перекриття сусідніх фрагментів однієї сторінки прибираються перед генерацією; порядок сторінки й прив’язка цитат до документа збережені. Автотест перевіряє відновлення тексту після нарізання на фрагменти.

## Голос, камера, погода — 21 жовтня 2026

`/live` — окрема мобільна сторінка Gemini Live. Перед початком потрібне підтвердження передачі голосу/кадрів до Google; камера окремо вмикається користувачем. Ключ не надходить у браузер. WebSocket `/api/live` перевіряє cookie і точний Origin, повторно перевіряє сесію кожні 10 секунд. Один дзвінок на процес, до 5 хвилин, кадр до 1/с і до 250 KB, аудіо PCM16 16 kHz. Сервер обмежує розмір WebSocket, байтову швидкість аудіо та кількість звернень до джерел. Модель за замовчуванням `gemini-3.8-live`, змінюється `GEMINI_LIVE_MODEL`. Вона окрема від текстового пулу; тариф і квоти залежать від проєкту Google. Без зміни білінгу.

Голосова відповідь відтворюється потоково (PCM24k), текст показується поруч. Підтримано перебивання, вимкнення мікрофона/камери, завершення, ручне повторне підключення після обриву. Повторне підключення починає нову розмову; безшовне відновлення історії ще не реалізовано. При приховуванні вкладки пристрої вимикаються. Застосунок не зберігає запис або транскрипт дзвінка; умови обробки Google діють окремо. `farm_library` звертається до перевіреного RAG, `farm_weather` — до прогнозу. Увімкнено включення кадрів поза мовленням і стиснення контексту для довших відеосеансів.

На телефоні потрібні HTTPS, дозвіл на мікрофон і камеру та браузер з AudioWorklet. `127.0.0.1` на телефоні означає сам телефон. Для Oracle використовуйте домен через Caddy (WebSocket проксі підтримується), не відкривайте порт 8000 назовні. API має бути доступним серверу через вихідний HTTPS/WSS.

`/api/weather`, `/farm#weather` та погодні питання в чаті отримують поточні модельні оцінки, погодинний і 7-денний прогноз Open-Meteo. Кеш 15 хвилин, таймаути, пауза після збою; прострочений кеш не видається як актуальний. Одиниці вітру — м/с, часовий пояс Europe/Kyiv, відсутні дані не перетворюються на нулі. Це модельна сітка, не датчик на полі. Для комерційного використання потрібні відповідні умови Open-Meteo; `OPEN_METEO_API_KEY` вмикає customer-api. Публічний endpoint призначений для некомерційної розробки, ключ/оплата автоматично не створюються.

Швидкодія: погодні питання не викликають Gemini або векторний пошук; самодостатні довгі питання про культуру обходять окреме переписування моделлю; embedding-модель спочатку завантажується з локального кешу, без мережевих перевірок. Live озвучує частинами. Повні агрономічні відповіді з перевіркою джерел усе ще можуть чекати провайдера; гарантії часу немає.

Додані регіональні рекомендації НААН 2025: осінні роботи (41 сторінка), весняні (57). Імпорт: `HF_HUB_OFFLINE=1 .venv/bin/python -m scripts.import_regional`. Старі матеріали не підтверджують поточні спалахи чи реєстрацію препаратів. Пошук розширює вибірку семантичних кандидатів, прибирає повторні сторінки й застосовує невелику лексичну поправку за конкретними словами запиту; фінальний контекст до 10 сторінок.

Перевірки: `.venv/bin/python -m pytest -q`; `node scripts/check_audio.cjs`. Реальна перевірка з тестовою авторизацією, синтетичним кадром і Google: `.venv/bin/python -m scripts.check_live_relay --weather` (витрачає квоту). Жодного доступу до пристроїв користувача.

З наданої добірки реєстри препаратів і сортів тепер підключені (див. нижче). Ще не реалізовано: чинні етикетки, імпорт HRAC/FRAC/IRAC, ліцензований EPPO, PubChem та каталоги техніки. PPDB/CABI не скопійовано. Беларус і Case IH 2388 згадані в добірці іншого ШІ, але не підтверджені власником як техніка господарства. Для її налаштувань потрібні модель, рік/серійний номер та відповідний заводський посібник.

## Реєстри препаратів і сортів

`/farm#registers`: пошук за назвою, номером, діючою речовиною; для сорту можна додати культуру (усі слова мають збігтися). Приклади команд у чаті: `Перевір препарат: назва`, `Перевір сорт: назва культура`, `Чи зареєстрований препарат назва?`. Вони звертаються до структурованої SQLite-бази без генерації фактів Gemini. У голосовій розмові доступний інструмент `farm_registry`.

Офіційні джерела виявляються за посиланнями на сторінках me.gov.ua. Стан початкового імпорту 21.10.2026: файл препаратів 19.10.2026 (13 360 записів), файл сортів 16.10.2026 (26 714 записів з основного й виключеного аркушів). Це записи, не кількість дозволених препаратів або активних сортів. Історичні дублікати збережено, а не об’єднано за назвою. Дата файлу, перевірка джерела, SHA256, аркуш і рядок відокремлені. Байтові копії з SHA256 доступні після входу; зовнішній оригінал з часом може змінитися. Значення формул XLSX читаються з кешу видавця, формули не виконуються; невідомий строк не вважається чинним.

Під час пошуку джерело перевіряється, якщо остання успішна перевірка старша за 24 години. Це оновлення на запит, не фонова автоматизація. При збоях повторна спроба не частіше ніж раз на 5 хвилин; останні записи зберігаються, але `fresh_check=false`. Невідома структура, неоднозначна публікація або відсутня дата не замінюють робочу базу. Імпорт транзакційний. `/api/registers` показує стан; `/api/registers/search` виконує пошук.

`fresh_check` означає перевірку доступної оприлюдненої версії, а не підтвердження кожного запису в реальному часі. Скасування/призупинення та минулий строк мають окремі позначки. Майбутній строк не є дозволом на застосування; офіційна етикетка ще не імпортована. Відсутність збігу не доводить заборону, а реєстрація сорту не доводить його перевагу для поля. Результати включають точні рядки джерела без вигадування доз і оцінок урожайності. Реєстри не змішуються з PDF у векторній бібліотеці.

`data/registers.sqlite3` і `data/registers/` є відновлюваними копіями відкритих джерел; поточний backup-скрипт їх не включає. Умови джерела: посилання на me.gov.ua обов’язкове; приватний застосунок не перепубліковує таблиці відкрито. Подальші задачі: чинні етикетки, класифікатори HRAC/FRAC/IRAC та порівняльні випробування сортів.

## Погода разом із рішенням про польові роботи

Питання на кшталт «яка погода, чи підійде зараз молотитьь кукурудзу?» проходять агрономічний пошук, а не завершуються таблицею прогнозу. До бібліотечного контексту додається окремий погодний знімок: поточна оцінка, три доби та найближчі шість годин. Цитати Open-Meteo мають час отримання й посилання; до них не додаються вигадані сторінки PDF. Якщо погодний API недоступний, питання про роботу зберігається, а поточні умови не оцінюються.

Відповідь має відрізняти вологість повітря від зерна, невідомі польові умови від заборони роботи та загальну таблицю стиглості від норм збирання конкретної культури. Для обмолоту кукурудзи запитуються виміряна вологість і можливість сушіння. Перевірка дослівності цитат не гарантує правильності агрономічного висновку; потрібні подальші контрольні приклади. Регресії: `tests/test_mixed_weather.py`; живий приклад: `evaluation/corn-harvest-weather.json`.

## Комплексні та рідкі добрива

`/farm#calculator` і POST `/api/calculations/nutrients` перераховують задану кількість N, P₂O₅ або K₂O у масу продукту за масовими частками з етикетки. Показуються всі три супутні компоненти на гектар. Літри з’являються лише з введеною густиною кг/л; жодної типової густини чи складу за назвою не підставляється. Елементарні P/K, доступність живлення, оптимальна норма й строки не визначаються. Старий endpoint азоту збережено. Перевірки: `tests/test_nutrients.py`.
